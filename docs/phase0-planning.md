## 1. 結論：MVPスコープと優先順位

### MVPの一言定義

> **「アンソロジー企画を軸に、収録作・関連記事を横断して回遊できる、読書体験型の文芸ポータル」**

### MVPで作るもの（Must）

| 優先順位 | 機能 | 根拠 |
|---|---|---|
| 1 | アンソロジー企画一覧ページ | サイトの核。最初に投入すべき看板コンテンツ |
| 2 | アンソロジー企画詳細ページ | 企画→収録作の導線の起点 |
| 3 | 収録作一覧・詳細ページ | 作品単位の到達点。検索流入の受け皿。全文掲載で読破体験提供（B-4確定） |
| 4 | 記事一覧・詳細ページ | 編集方針の表明と回遊の補助 |
| 5 | スポット一覧・詳細ページ | スコーン店・公園等の場所紹介。B-2確定によりMustに昇格。生成画像・施設写真対応（B-5確定） |
| 6 | トップページ | エントリーポイント。新着＋特集スポット表示 |
| 7 | タグ検索・絞り込み | 横断回遊の最重要機能 |

### MVPで作らないもの（除外・理由付き）

| 除外機能 | 理由 |
|---|---|
| ユーザー登録／ログイン | 初期は読む体験に集中。運用負荷が跳ね上がる |
| コメント機能 | モデレーション工数が見合わない |
| 有料会員・課金 | マネタイズはフェーズ2以降で検討。広告・寄付モデルで対応（D-2確定） |
| 検索エンジン全文検索 | タグ絞り込みで代替。スケール後に追加 |
| 著者マイページ | 寄稿者管理は別チャネル（Notion等）で代替 |
| RSS自動配信 | 手動更新フローが安定してから追加 |
| 多言語対応 | 日本語コンテンツ中心でMVP固定 |

### 3-6. 運用設計

#### コンテンツ更新フロー（1名エンジニア体制・A-3簡略確定）

A-1の回答（1名・エンジニア）とA-3の回答（簡略フロー）を受け、多段階承認フローは省略。GitベースのCMSを前提とする。

```
[担当者（兼：編集・エンジニア）]
  ↓ MDXファイルを作成（ローカル or GitHub上）
  ↓ AI生成コンテンツをフォーマットに合わせて整形・タグ設定
  ↓ git push → CI自動プレビュー（Netlify Preview等）【C-2確定：Netlify】
  ↓ プレビューURLで最終確認
  ↓ mainブランチにマージ → 自動デプロイ・公開
  ↓ 公開後30分以内にSNS投稿
```

#### 最低限の公開前チェックリスト

- [ ] タイトル・本文に意図しない誤字・不自然な表現がないか（AI生成物のレビュー）
- [ ] AI生成コンテンツである旨の表示が必要か確認した（方針決定後に対応）
- [ ] 画像のライセンスが確認済みか。生成画像の場合はツールTOS確認済み（B-5対応）
- [ ] スポット写真は撮影許可が確認済みか（R-3対策）
- [ ] OGP画像・タイトル・descriptionが設定されているか
- [ ] タグが適切に設定されているか（3〜5タグ推奨）
- [ ] 関連コンテンツのリンクが正しく設定されているか
- [ ] モバイルプレビューで表示を確認したか
- [ ] スペルミス・リンク切れがないか

#### 更新頻度目安（A-2確定：週1本記事）

| コンテンツ種別 | 頻度 | 担当工数目安 | 備考 |
|---|---|---|---|
| アンソロジー企画 | 月1本 | 高（企画から公開まで2〜4週間） | 初期10本を段階投入予定（B-3確定） |
| 収録作 | 月4〜8本 | 中（企画紐付き・一括公開も可） | AI生成のため短期量産可。全文掲載（B-4確定） |
| 記事 | **週1本（月4本）** | 中（1〜2週間） | A-2確定値 |
| スポット（場所紹介） | 月1〜2本 | 中（取材・写真撮影が必要。施設許可確認含む） | 生成画像・施設写真対応（B-5確定） |

**合計更新頻度**：約週1.5本以上（記事1 + 企画・スポット・作品の混合）

#### バッファ戦略（R-5対策）

- 記事バッファ：常に2〜3本ドラフト保持（週1本更新の4週分カバー）
- 企画バッファ：月1本のペースで先行企画企画を1本常に準備
- スポット候補：取材対象の候補リストを常に3〜5件確保

### 3-7. リスク一覧と対策

| # | リスク | 分類 | 深刻度 | 発生確率 | 対策 |
|---|---|---|---|---|---|
| R-1 | AI生成コンテンツへの読者・社会的信頼失墜 | 品質/評判 | 高 | 中 | AI生成である旨の表示方針を早期に決定（表示 or 非表示の根拠を明文化）。透明性重視を推奨 |
| R-2 | AI生成コンテンツの著作権帰属の法的グレーゾーン | 著作権 | 中 | 中 | 現行法（2026年時点）では生成AIの出力物に著作権は発生しないとされているが、利用ツールのTOSを確認。生成ツール・プロンプト・パラメータを内部記録 |
| R-3 | スポット写真・施設の無許可撮影・掲載 | 著作権/法的 | 高 | 中 | **屋内撮影は施設に事前許可を取得**（B-5確定対応）。許可記録をファイル管理。content-types.md の `photo_permission` フラグで管理。無許可の場合は status: draft で公開ブロック |
| R-4 | 画像素材の権利未確認（表紙・挿絵等） | 著作権 | 中 | 高 | **CC0・CC BY素材のみ使用**（B-5確定：生成画像も含む）。AI画像生成ツール利用時はライセンスTOSを確認。ソース・ライセンス情報を MDXメタデータに記録 |
| R-5 | 更新停滞によるコンテンツ鮮度低下 | 運用 | 中 | 高 | **最小更新頻度を決め、バッファ記事を常に2〜3本ストック**（A-2確定：週1本記事）。AI生成でバッファ補充が容易。更新が週1本を下回る場合はSNS発信強化で露出を補完 |
| R-6 | 担当者1名によるバス係数リスク | 運用 | 高 | 中 | **運用手順書をGitリポジトリ内に保持**。CIによる自動デプロイで依存スキル最小化。緊急時の代理手順を整備。簡略フロー（A-3確定）により属人化を低減 |
