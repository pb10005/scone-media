## 1. 結論：MVPスコープと優先順位

### MVPの一言定義

> **「アンソロジー企画を軸に、収録作・関連記事を横断して回遊できる、読書体験型の文芸ポータル」**

### MVPで作るもの（Must）

| 優先順位 | 機能 | 根拠 |
|---|---|---|
| 1 | アンソロジー企画一覧ページ | サイトの核。最初に投入すべき看板コンテンツ |
| 2 | アンソロジー企画詳細ページ | 企画→収録作の導線の起点 |
| 3 | 収録作一覧・詳細ページ | 作品単位の到達点。検索流入の受け皿 |
| 4 | 記事一覧・詳細ページ | 編集方針の表明と回遊の補助 |
| 5 | トップページ | エントリーポイント。新着＋特集スポット表示 |
| 6 | タグ検索・絞り込み | 横断回遊の最重要機能 |

### MVPで作らないもの（除外・理由付き）

| 除外機能 | 理由 |
|---|---|
| ユーザー登録／ログイン | 初期は読む体験に集中。運用負荷が跳ね上がる |
| コメント機能 | モデレーション工数が見合わない |
| 有料会員・課金 | マネタイズはフェーズ2以降で検討 |
| 検索エンジン全文検索 | タグ絞り込みで代替。スケール後に追加 |
| 著者マイページ | 寄稿者管理は別チャネル（Notion等）で代替 |
| RSS自動配信 | 手動更新フローが安定してから追加 |
| 多言語対応 | 日本語コンテンツ中心でMVP固定 |

### 3-2. MVP要件（Must／Should／Could）

#### Must（ローンチに必須）

- [ ] トップページ（新着スポット3〜5件、注目企画1〜2件、新着記事3件）
- [ ] アンソロジー企画一覧ページ（タグ絞り込み対応）
- [ ] アンソロジー企画詳細ページ（収録作リスト付き）
- [ ] 収録作詳細ページ（全文 or 抜粋＋企画への戻り導線）
- [ ] 記事一覧・詳細ページ
- [ ] タグページ（タグ一覧 + タグ別コンテンツ一覧）
- [ ] 「このサイトについて」ページ（ブランドステートメント）
- [ ] OGP/メタタグ設定（SNSシェア最適化）
- [ ] モバイルレスポンシブ

#### Should（第1スプリント後に追加）

- [ ] スポット詳細ページ（※スポットの定義確認後）
- [ ] 「寄稿について」ページ（問い合わせフォームorリンク）
- [ ] 関連企画・関連記事ウィジェット（回遊強化）
- [ ] サイト内検索（タグ外のキーワード検索）
- [ ] RSSフィード

#### Could（フェーズ2以降で検討）

- [ ] 著者プロフィールページ
- [ ] ブックマーク機能
- [ ] ニュースレター登録
- [ ] 多言語対応
- [ ] 有料コンテンツ・課金機能

### 3-3. コンテンツタイプ定義

詳細は [`content-types.md`](./content-types.md) を参照。

| タイプ | 説明 | 主な想定本数（初期） |
|---|---|---|
| アンソロジー企画（anthology） | テーマを定めた作品集企画。複数の収録作を束ねる親コンテンツ | 3〜5本 |
| 収録作（work） | アンソロジー企画に属する個別作品（小説・詩・エッセイ等） | 15〜30本 |
| 記事（article） | 編集部による解説・書評・インタビュー等 | 5〜10本 |
| スポット（spot） | ※定義確認待ち。暫定：特集ピックアップ記事 or 場所紹介 | 未定 |
| タグ（tag） | ジャンル・テーマ・形式など横断分類。コンテンツに複数付与可能 | 20〜40タグ |

### 3-4. サイトマップ／主要導線

詳細は [`sitemap.md`](./sitemap.md) を参照。

```
トップ (/)
├── アンソロジー企画一覧 (/anthologies)
│   └── アンソロジー企画詳細 (/anthologies/[slug])
│       └── 収録作詳細 (/works/[slug])
├── 記事一覧 (/articles)
│   └── 記事詳細 (/articles/[slug])
├── スポット一覧 (/spots) ← Should
│   └── スポット詳細 (/spots/[slug])
├── タグ一覧 (/tags)
│   └── タグ別コンテンツ (/tags/[tag])
├── このサイトについて (/about)
└── 寄稿について (/contribute) ← Should
```

#### 主要導線（回遊仮説）

| 流入元 | 想定導線 | 目標アクション |
|---|---|---|
| 検索（作品名・作家名） | 収録作詳細→企画詳細→同タグ企画 | タグ回遊・再訪 |
| 検索（テーマ・ジャンル） | タグページ→企画一覧→企画詳細 | 企画へのエンゲージメント |
| SNSシェア | 記事詳細→関連企画→収録作 | 滞在時間↑ |
| 直接アクセス・ブックマーク | トップ→新着確認→記事 or 企画 | 定期再訪 |

### 3-5. KPI定義

詳細は [`kpi.md`](./kpi.md) を参照。

#### 北極星指標（North Star Metric）

> **「月間アクティブ回遊セッション数」**  
> 定義：1セッション内で2ページ以上を横断したセッションの月間合計数

#### KPI対応表

| KPI | 指標 | 計測方法 | ダッシュボード |
|---|---|---|---|
| 認知 | 月間UU | GA4 / 解析ツール | 週次レポート |
| 回遊 | PV/セッション | GA4 | 週次レポート |
| 再訪 | リピート訪問率（%） | GA4 ユーザー属性 | 月次レポート |
| エンゲージメント | 平均エンゲージ時間 | GA4 | 週次レポート |
| コンテンツ人気 | 記事・作品別PV | GA4 コンテンツレポート | 週次レポート |
| SNS拡散 | SNSシェア数 | OGP計測 + 手動集計 | 月次レポート |
| 導線効果 | 企画→収録作クリック率 | GA4 イベント | 月次レポート |

| イベント名 | トリガー | パラメータ |

### 3-6. 運用設計

#### コンテンツ更新フロー

```
[執筆者]
  ↓ 原稿を所定フォーマットで提出（Google Docs or Notion）
[編集担当]
  ↓ 内容確認・著作権確認・タグ設定
[校正担当]（兼任可）
  ↓ 誤字脱字・表記統一チェック
[公開担当]
  ↓ CMSに入力・プレビュー確認
  ↓ スケジュール公開 or 即時公開
[SNS告知担当]
  ↓ 公開後30分以内にSNS投稿
```

#### 最低限の公開前チェックリスト

- [ ] 著者名・作品名の表記が正しいか
- [ ] 著作権・掲載許諾が取得済みか（外部作品の場合）
- [ ] 画像のライセンスが確認済みか
- [ ] OGP画像・タイトル・descriptionが設定されているか
- [ ] タグが適切に設定されているか（3〜5タグ推奨）
- [ ] 関連コンテンツのリンクが正しく設定されているか
- [ ] モバイルプレビューで表示を確認したか
- [ ] スペルミス・リンク切れがないか

#### 更新頻度目安（暫定）

| コンテンツ種別 | 頻度 | 担当工数目安 |
|---|---|---|
| アンソロジー企画 | 月1本 | 高（企画から公開まで2〜4週間） |
| 収録作 | 月4〜8本 | 中（企画紐付き・一括公開も可） |
| 記事 | 月2〜4本 | 中（1〜2週間） |
| スポット | 月1〜2本 | 低〜中（定義確認後に再設定） |

### 3-7. リスク一覧と対策

| # | リスク | 分類 | 深刻度 | 発生確率 | 対策 |
|---|---|---|---|---|---|
| R-1 | 外部作品の無断掲載による著作権侵害 | 著作権 | 高 | 中 | 掲載許諾書テンプレを作成し、公開前チェックリストに組み込む。許諾なしは掲載不可を運用ルール化 |
| R-2 | 引用範囲の超過（著作権法32条違反） | 著作権 | 中 | 中 | 引用は主従関係が明確な範囲に限定。全文掲載は必ず権利者許諾を取得 |
| R-3 | 画像素材の権利未確認 | 著作権 | 中 | 高 | フリー素材（CC0またはCC BY）のみ使用。有料ストック利用時はライセンス種別を記録 |
| R-4 | 更新停滞によるコンテンツ鮮度低下 | 運用 | 中 | 高 | 最小更新頻度を決め、バッファ原稿を常に2〜3本ストック。停滞時の緊急対応フローを定義 |
| R-5 | 担当者のバーンアウト・離脱 | 運用 | 高 | 中 | 手順書を整備し属人化を排除。最低2名が各ロールを担えるようにする |
| R-6 | 外部寄稿者との品質トラブル | 品質 | 中 | 中 | 寄稿ガイドライン（文字数・形式・禁止事項）を事前共有。リジェクト基準を明文化 |
| R-7 | 個人情報漏洩（寄稿者連絡先等） | セキュリティ | 高 | 低 | 問い合わせフォームはHTTPS必須。連絡先情報は非公開ストレージ（Notionアクセス制限等）で管理 |
| R-8 | SEO初期ペナルティ（重複コンテンツ等） | 品質/技術 | 中 | 低 | canonicalタグを適切に設定。タグページの重複コンテンツ対策（noindex or ユニーク導入文） |
| R-9 | スポット定義の不明確さによる開発手戻り | 設計 | 中 | 高 | **最優先：B-2の質問に回答を得てからスポット開発着手** |

### 3-9. 意思決定メモ

#### 論点1：スポットの位置づけ

| 案 | 内容 | メリット | デメリット |
|---|---|---|---|
| 案A | 編集部ピックアップ（既存コンテンツのキュレーション） | 新規制作不要。運用負荷低 | 独自性が薄い |
| 案B | 場所・空間の紹介記事（読書スポット等） | ブランドの世界観拡張 | 定期的な取材が必要。運用負荷高 |
| 案C | インタビュー記事（作家・関係者） | 一次情報で差別化 | 取材コスト・許諾管理が発生 |

**推奨**：MVPは案Aで開始し、運用が安定したら案Cへ拡張。案Bは体制強化後に検討。

#### 論点2：CMS選定

| 案 | ツール | メリット | デメリット |
|---|---|---|---|
| 案A | Notion + 外部CMS（Contentful等） | 非エンジニアが使いやすい | コスト発生。連携設計が必要 |
| 案B | headless CMS（Sanity, Microstack等） | 柔軟性高い | エンジニアスキル必要 |
| 案C | Next.js + MDX（ファイルベース） | コスト最小・自由度高い | 非エンジニアによる更新が困難 |

**推奨**：運用者にエンジニアが含まれる → 案C。含まれない → 案A（Notion + Contentful）。  
**確認事項：A-1の回答で決定。**

#### 論点3：ローンチタイミング

| 条件 | 推奨タイミング |
|---|---|
| 企画3本・記事5本・タグ20本が揃う | ソフトローンチ（招待制 or 非公開URL） |
| 企画5本・記事10本・スポット3本が揃う | パブリックローンチ |

**推奨**：コンテンツ不足でのローンチは直帰率を跳ね上げるため、最低ラインを厳守する。
