## 4. ページ・機能仕様

### 4-1. 寄稿問い合わせページ（`/contribute`）

**目的**：寄稿希望者（ペルソナB）の問い合わせ窓口を提供し、コンバージョンを計測する

**表示要素**：
1. 寄稿方針の説明（どんな作品を求めているか・AI生成のみか外部作家も受け付けるか）
2. 問い合わせフォーム（React Hook Form + Netlify Forms or Formspree）
3. 確認事項チェックリスト（著作権・掲載条件）

**フォームフィールド**：

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| `name` | String | ○ | 氏名またはペンネーム |
| `email` | Email | ○ | 返信先メールアドレス |
| `inquiry_type` | Enum | ○ | `work_submission`（作品投稿）/ `interview`（取材依頼）/ `other` |
| `message` | Text | ○ | 問い合わせ内容（500字以内推奨） |
| `agree_terms` | Boolean | ○ | 掲載条件への同意チェックボックス |

**GA4イベント**：

| イベント | トリガー |
|---|---|
| `contribute_click` | `/contribute`ページへの導線クリック（全ページのフッター等） |
| `contact_submit` | フォーム送信成功 |
| `contact_form_start` | フォームへの最初の入力 |

**受け入れ基準**：
- [ ] フォームがスパム対策済み（honeypot or reCAPTCHA）
- [ ] 送信後のサンクスメッセージ/ページ遷移が機能する
- [ ] `contact_submit` イベントがGA4に送信されることを確認済み
- [ ] モバイルで問題なく入力・送信できる

---

### 4-2. RSS フィード（`/feed.xml`）

**目的**：フィードリーダー・RSSアグリゲーターへの配信。リピーターの自動再訪を促す

**仕様**：
- フォーマット：RSS 2.0（または Atom）
- エンドポイント：`/feed.xml`
- 含めるコンテンツ：記事（article）・アンソロジー企画（anthology）・スポット（spot）の最新20件（混合）
- 更新頻度：コンテンツ公開時に自動更新（Next.js の Route Handler で生成）
- フィード項目の要素：`title`, `link`, `description`（excerpt or 本文冒頭200字）, `pubDate`, `category`（タグ）

**実装方針**：
```typescript
// app/feed.xml/route.ts
// getAllPublishedContent() でarticles/anthologies/spotsをマージ
// rss パッケージ (MIT) or 手動XML生成
```

**受け入れ基準**：
- [ ] `/feed.xml` でXMLが返される
- [ ] RSSバリデーター（https://validator.w3.org/feed/）で合格
- [ ] `<head>` に `<link rel="alternate" type="application/rss+xml">` が設置されている

### 4-3. 著者プロフィールページ（`/authors/[slug]`）

**目的**：寄稿者・AI生成作品の「著者（クレジット）」を一覧化し、作品発見の導線を追加する

**表示要素**：
- 著者名・プロフィール文（100〜300字）
- プロフィール画像（任意）
- 担当した収録作一覧（カード表示）
- 担当した記事一覧

**データモデル（新規）**：

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| `name` | String | ○ | 表示名 |
| `slug` | String | ○ | URLスラッグ |
| `bio` | Text | ○ | プロフィール（100〜300字） |
| `avatar_image` | Image | - | プロフィール画像 |
| `is_ai_persona` | Boolean | ○ | AIペルソナフラグ（AI生成作品の架空著者の場合 `true`） |
| `social_links` | Object | - | `{ twitter, website }` 等 |

**Phase1との差分**：
- Phase1では `author_name`（文字列）と `author_bio`（テキスト）をworkのフロントマターに直書きしていた
- Phase2では著者データを独立した `content/authors/` に切り出し、`/authors/[slug]` ページを新設する
- 既存workのフロントマターに `author_slug` フィールドを追加（後方互換性：`author_slug` なしの場合は `author_name` をフォールバック）

### 4-4. ブックマーク機能

**目的**：ログイン不要で「あとで読む」を実現。リピーター率向上に貢献

**設計方針**：
- **ストレージ**：`localStorage`（サーバーサイド不要・認証不要）
- **対象コンテンツ**：work・article・anthology・spot
- **UIコンポーネント**：各詳細ページのブックマークボタン（ハート or ブックマークアイコン）
- **ブックマーク一覧**：`/bookmarks` ページ（SSR不要・クライアントのみで描画）

**データ構造（localStorage）**：
```typescript
// localStorage key: "scone_bookmarks"
type Bookmark = {
  type: 'work' | 'article' | 'anthology' | 'spot';
  slug: string;
  title: string;
  saved_at: string; // ISO8601
};
```

**受け入れ基準**：
- [ ] ブックマーク追加・削除が即時反映される
- [ ] ページリロード後もブックマークが保持される
- [ ] `/bookmarks` ページでブックマーク一覧が表示される（0件時の空状態表示も含む）
- [ ] SSRとのhydration mismatchが発生しない（useEffectでlocalStorage読み込み）

### 4-5. サイト内全文検索

**目的**：タグ絞り込みの補完。キーワードで横断検索できる

**実装方針**：

| 案 | ツール | 方式 | 採用判断 |
|---|---|---|---|
| 案A | **Pagefind**（MIT） | 静的インデックス・ビルド時生成 | **推奨**。Next.js Static Exportと相性◎ |
| 案B | Fuse.js（Phase1既存） | クライアントサイドメモリ内検索 | コンテンツが増えると重くなる。既存活用で差分コスト小 |
| 案C | Algolia/Meilisearch | 外部サービス/セルフホスト | コスト・運用負荷大。Phase3以降 |

**推奨**：案AのPagefindでビルド時インデックスを生成し、`/search` ページに検索UIを設置。Fuse.jsはタグフィルターに引き続き使用。

**エンドポイント**：`/search?q=<keyword>`

### 4-6. スポット地図埋め込み

**目的**：スポット詳細ページに地図を表示し、実際に訪れる動機を高める

**実装方針**：
- **Leaflet.js（BSD-2-Clause）+ OpenStreetMap（ODbL）**を採用
  - Phase0 C-1（商用利用可OSS）の制約をクリア
  - Google Maps APIの費用・利用規約リスクを回避
- スポット詳細ページの住所・アクセスセクションの下に地図を表示
- `latitude`/`longitude` が未設定のスポットは地図非表示（GoogleMapsリンクのみ）

**フィールド追加（spot）**：

| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| `latitude` | Number | - | 緯度（地図表示に使用） |
| `longitude` | Number | - | 経度（地図表示に使用） |
| `map_zoom` | Number | - | デフォルトズームレベル（デフォルト15） |

## 6. SEO・パフォーマンス深化

### 6-1. 独自ドメイン移行（最優先・Phase2開始時）

Phase0 論点5（C-4）の確定方針に従う：

```
タイムライン（Phase2開始時に実施）:
1. 独自ドメイン取得（例: scone-media.jp または scone-media.com）
2. Netlify でカスタムドメイン設定
3. netlify.app → カスタムドメインへの 301 リダイレクト設定
4. GA4 のプロパティ設定を更新（ドメイン変更を反映）
5. Google Search Console にカスタムドメインを登録・サイトマップ再送信
```

**SEO連続性の担保**：
- 301リダイレクトで既存インデックス・被リンクを継承
- `sitemap.xml` の `<loc>` をカスタムドメインに更新
- OGP の `og:url` をカスタムドメインに更新

### 6-2. 構造化データ（JSON-LD）実装

Phase1で未対応の構造化データをPhase2で追加：

| ページ | Schema.org タイプ | 実装内容 |
|---|---|---|
| 収録作詳細 | `CreativeWork` / `Article` | `name`, `author`, `datePublished`, `inLanguage` |
| アンソロジー企画詳細 | `Collection` | `name`, `description`, `hasPart`（収録作リスト） |
| 記事詳細 | `Article` | `headline`, `author`, `datePublished`, `image` |
| スポット詳細 | `LocalBusiness` / `Place` | `name`, `address`, `geo`（lat/long）, `openingHours` |
| 著者プロフィール | `Person` | `name`, `description`, `url` |
| トップページ | `WebSite` + `Sitelinks Searchbox` | サイト全体のSearchbox誘導 |

### 6-3. Core Web Vitals 目標値

| 指標 | Phase1目標 | Phase2目標 | 対応策 |
|---|---|---|---|
| LCP | < 2.5s | < 2.0s | next/image の priority 最適化・フォントサブセット化 |
| CLS | < 0.1 | < 0.05 | 画像サイズ明示・動的コンポーネントのSkeleton導入 |
| INP | < 200ms | < 150ms | Suspense境界の細粒化・遅延読み込み拡大 |

### 6-4. タグページSEO方針の確定

| 選択肢 | メリット | デメリット | 採用判断 |
|---|---|---|---|
| `noindex` 設定 | 重複コンテンツリスク排除・クロールバジェット節約 | タグページ経由の検索流入ゼロ | タグ数が50以上になったら採用 |
| ユニーク導入文を設置 | タグページからの検索流入を狙える | 運用コスト増（全タグに導入文が必要） | **初期（タグ50以下）は採用推奨** |

**Phase2での対応**：タグページ全件にユニーク `description` を設定。タグ数が増えた場合に `noindex` へ切り替えを検討。

- **推奨サービス**：Ko-fi（無手数料・日本語対応）または OFUSE（日本特化）

- **表示文言例**：「スコーン・ポータルを応援する ☕」

### 7-3. 収益目標（暫定）

| 時期 | 広告収入目標 | 寄付目標 | 前提条件 |
|---|---|---|---|
| Phase2開始〜3ヶ月 | ¥0〜¥3,000/月 | ¥0〜¥1,000/月 | AdSense審査通過次第 |
| Phase2安定期（6ヶ月後） | ¥3,000〜¥10,000/月 | ¥1,000〜¥3,000/月 | 月間UU 4,000達成時 |

> **方針**：収益化は運用コスト（ドメイン・有料ツール費用）のカバーが最初の目標。過度な収益最大化はUX・コンテンツ品質と相反するため、「コストカバー優先」とする。

## 8. インフラ・ドメイン移行

### 8-1. 独自ドメイン取得（Phase2最初の作業）

```
作業ステップ:
1. ドメイン候補の決定（例: scone-media.jp / scone-media.com / scone.media）
2. お名前.com / Cloudflare Registrar 等で取得（年額 ¥1,000〜¥2,000）
3. Netlify の [Domain management] でカスタムドメインを追加
4. DNS設定（Netlify DNSまたは取得先のDNSサーバーでCNAME設定）
5. HTTPS証明書の自動発行確認（Let's Encrypt・Netlify管理）
6. 旧netlify.appドメインからの301リダイレクト設定
```

### 8-2. Netlify プラン

| 現状 | Phase2での変更 | 条件 |
|---|---|---|
| Netlify 無料（Starter）プラン | 当面維持 | 月間帯域100GBを超えた場合 Pro プランへ移行 |
| ビルド時間 300分/月 | 当面維持 | コンテンツが大幅増加した場合に再評価 |

### 8-3. Cookie同意バナー強化（GA4対応）

- **CMP（同意管理プラットフォーム）**：`react-cookie-consent`（MIT）で最低限実装
- **同意を取得する処理**：GA4の `gtag.js` 読み込みを同意後にのみ実行
- **拒否した場合**：計測なし（ゼロデータ）で動作すること
- Phase1でGA4と同時に実装済みでない場合はPhase2で必ず対応する

| R2-1 | AdSense審査が通らない | 中 | 中 | コンテンツ量・品質を充実させてから申請。代替として寄付モデルを先行実装 |

| R2-5 | AIペルソナ著者の開示問題 | 高 | 中 | `is_ai_persona: true` の著者ページに「このプロフィールはAIが生成したペルソナです」と明示。Phase0 R-1への対策として透明性を担保 |
| R2-6 | Phase2スコープ膨張によりPhase1品質が固まる前に着手 | 中 | 高 | Phase1の全ゲーティング条件（G-1〜G-5）をクリアしてからPhase2開始 |
| R2-7 | 寄稿フォームへのスパム | 中 | 高 | Netlify Formsのスパムフィルタリング + honeypotフィールドで対処 |
